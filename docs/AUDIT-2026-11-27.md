## 4. Technologie a nástroje

- PHP: `>=8.3`, Composer platforma `8.3.0`.
- Aktuální lockfile používá hlavní komponenty Nette 3.3.1; Composer constraints zůstávají kompatibilní s `^3.2`.
- Nette Database Explorer pro aplikační databázový přístup; Nextras DBAL/Migrations pro migrace a testovací infrastrukturu.
- MySQL 8.4 v CI; lokální vývoj uživatele používá MySQL 8.4.13.
- PHPStan 2.3.5 level max, Nette Tester 2.7.0, PHP-CS-Fixer 3.95.29 a Deptrac 4.7.2.
- HTMLPurifier 4.19.1, Intervention Image 4.4.0, intervention/gif 5.0.2.
- Ublaboo DataGrid 7.2.0, HugeRTE 1.0.15, AdminLTE 4.10.2, Bootstrap 5.3.8, Bootstrap Icons 1.13.2, Naja 3.3.3.
- Node je připnut v `.nvmrc` na 26.13.0.

### Otevřený nesoulad npm

`package.json` a `package-lock.json` deklarují npm `>=12.2.2 <13`, zatímco lokální vývojové prostředí uživatele bylo naposledy uvedeno s npm 11.20.0. CI používá Node z `.nvmrc` a vypisuje skutečnou verzi npm, ale tento rozdíl je nutné před dalším standardizováním toolchainu výslovně vyřešit. V rámci tohoto dokumentačního auditu nebyl požadavek npm v package souborech změněn.

### Bootswatch Cosmo

Bootstrap 5.3.8 je v npm závislostech. Aktuální Sass vstupy importují Bootstrap; Bootswatch Cosmo není v aktuálním build vstupu ani v npm závislostech. Cosmo zůstává schváleným cílem pro budoucí veřejný Front, nikoliv součástí aktuálně sestavovaného UI. Admin používá AdminLTE 4.

## 6. Bezpečnostní model médií

- Nové i historicky backfillované položky jsou soukromé ve výchozím stavu.
- Veřejnost vzniká pouze explicitním publikováním administrátorem.
- `published_at` je autoritativní podmínka veřejného čtení; `public_token` je neprůhledný identifikátor, nikoliv autorizační tajemství.
- Veřejný endpoint vydává pouze povolené deriváty, nikdy originál.
- HugeRTE picker vrací pouze publikované položky.
- HTMLPurifier povoluje pouze kontrolovaný interní tvar URL médií.

## 8. F5-25 – životní cyklus produktu (HOTOVO)

Nové strukturální migrace `2026-11-27-100000-product-archive-terminal.sql` a `2026-11-27-102000-product-image-derivative-reuse.sql` vynucují terminální stav `archived` a dovolují sdílení derivátových cest mezi produktovými vazbami. Trigger nedovolí opustit stav `archived`. Stávající archivovací trigger deaktivuje aktivní varianty. Aplikační `ProductLifecycleService` kontroluje oprávnění a povoluje vytvoření kopie pouze z archivovaného produktu.

Kopie dostává nové ID produktu a variant, jedinečný kód produktu a nová SKU; EAN se nepřenáší. Kopírují se překlady/SEO, kategorie, typ a daňová třída, atributy, osy a kombinace variant, zákaznické volby včetně příplatků, aktuální ceny a vazby na sdílená média. Výchozí varianta zůstává označená, ale neaktivní. Přenáší se pouze politika skladu (`track_stock`, `allow_backorder`); množství i rezervace jsou nulové. Cenová historie, skladové pohyby, objednávky, košíky a produktové vztahy se nekopírují. Katalogové vazby na deriváty se kopírují s novým ID obrázku, ale sdílejí stejný storage path. Nová migrace odstranila unikátní index z vazební tabulky; fyzickou unikátnost souboru nadále vynucuje `media_asset_derivative.storage_key`.

GitHub Actions run `46077797137` úspěšně ověřil dopředné migrace MySQL 8.4, **89 testů**, PHPStan, coding standard a Deptrac. Následně uživatel potvrdil aplikaci migrací v produkční i testovací databázi, úspěšný lokální `check.bat` a ruční ověření archivace/kopie v administraci. Původní seed archivace byl obnoven byte-for-byte; šest překladů kopírování produktu je v samostatném seedu `2026-11-27-103000-seed-catalog-product-copy.sql`.
